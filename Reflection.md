### 1. What were the main strengths of using AI to draft the README and R Markdown documentation?

The AI produced a README structure quickly. It proposed sections (Overview, Installation, Usage, Project Structure, License) that match how typical GitHub repositories are laid out. Its Markdown (headers, code blocks, tables, lists) was correctly formatted on the first attempt, which saved time on syntax. For the `.Rmd` file, it helped me sort the content into Purpose, Inputs, Outputs and Script Structure sections, and it suggested code-chunk examples.

### 2. What limitations or weaknesses did you notice in the AI-generated content, and how did you address them?

The first drafts were generic and longer than needed. The AI also invented folder names and file paths that did not match my project, and it added explanatory text that made the documentation less concise.

I addressed these issues by:
- Checking every file path and function name against the actual script
- Cutting long paragraphs and removing repeated sentences
- Replacing generic wording with specifics from my project
- Previewing the Markdown and knitting the `.Rmd` to catch rendering problems
- Rewriting the reflection answers and the AI disclosure in my own words

### 3. How did you ensure ethical use of AI (attribution, validation) in this assignment, and what did you learn about AI-assisted workflows?

I followed the course AI rules:
- Put the AI Assistance Declaration at the top of this file and at the top of the README, and included a disclosure at the bottom of the README
- Saved the main prompts in `Appendix_AI_Prompts.md`
- Reviewed every AI output before using it
- Used AI only as a writing and structure assistant, not for calculations or real data

**Key learning:** AI drafts documentation quickly, but its errors are specific and easy to miss. A plausible file path that does not exist, or an example output that the script would never print, only shows up when you check each claim against the project itself.
